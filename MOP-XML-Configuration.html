Part 2 — Section Descriptions
GLOBALXML / Global Settings  — unique to XML-based mode
xmlBuilder
Selects the XML generation strategy.
netconf-soi = Nokia SOI NETCONF-over-CLI.
Override per node type.
configAttributes
Key-value pairs added to every <config> envelope element: ne-version, ne-type, soi-version.
namespace / netconfNamespace
XML namespace for table elements and xmlns:xc on NETCONF operations. Set per-table in tables.
storagePath / includes
storagePath = temp dir on NE for XML files.
includes = reuse common YAML blocks from shared files.
§ 1preNodeHealthCheck
YAML keypreNodeHealthCheck
RunsBefore backup or any XML change
Node typeSBC (OAM_NODE)
Confirms SBC is stable with no outstanding PCS procedures, no audit errors, all VMs running, and no critical alarms. Any failure here blocks the activity entirely.
cm_adm -a health # health + no PCS virsh list --all # all VMs running sbc_health --test all # CRITI == 0 alarm_check --action health lcp_status # all ENABLED rem_srv_state --action display --set all
Static CLIRequiredSBC
§ 2backup
YAML keybackup
RunsAfter pre-health, before activity
Node typeSBC (OAM_NODE)
Exports the full NETCONF configuration of all planes (signaling + media) to XML files on the NE storage. These XML files are the rollback source if netconfprov delete fails.
netconfprov --plane signaling --readall \ > /storage/Signaling_<Hostname>_<DATE>.xml netconfprov --plane media --mediaid 1 --readall \ > /storage/MGW01_<Hostname>_<DATE>.xml
Static CLIRequiredSBC

RunsBefore auto-generated config blocks

§ 3bactivity › configuration  — CIQ-Driven XML (Core Activity)
YAML keyactivity.configuration
InputList of CIQ table names
OutputOne MOP block per table × action
TargetconfigurationTargetNode
The engine reads each CIQ JSON table, groups rows by Node and Action (CREATE / MODIFY / DELETE), builds a NETCONF XML payload per group, stages it on the NE, and applies it via netconfprov --onerror abort. XML is built from tables.<Name>.xmlTemplates if defined, or via the programmatic builder as fallback.
configuration: - CRFTargetList - PeeringSdpProfile configurationTargetNode: "OAM_NODE"
Generated MOP Block (per table × action)
##ACTIVITY_SBC_FL_CRFTargetList_CREATE_ACTIVITY_CONFIGURATION ## Description: Apply CREATE configuration for table CRFTargetList ## TargetNode: OAM_NODE $CREATE ACTIVITY_EXECUTION_ACTION_1=CRFTargetList_CREATE_CONFIGURATION ACTIVITY_EXECUTION_METHOD_1=CLI ACTIVITY_EXECUTION_PAYLOAD_1={ cat << 'XMLEOF' > /storage/SBC_FL_CRFTargetList_CREATE.xml <?xml version="1.0" encoding="UTF-8"?> <config ne="SBC-1" ne-version="R24.7" ne-type="SBC-signaling"> <CRFTargetList xmlns="http://nokia.com/yang/isbc-sig" xmlns:xc="http://nokia.com/yang/isbc-sig"> <Record xc:operation="create"> <TARGET_LIST_ID>TL-001</TARGET_LIST_ID> ... </Record> </CRFTargetList> </config> XMLEOF netconfprov --onerror abort /storage/...xml }
Auto XMLCIQ-DrivenRequiredSBC
TABLEStables  — XML Template Definitions per CIQ Table
namespace / xmlElement
Sets the XML namespace for this table's element and the element tag name. Defaults to defaultNamespace and the table name if omitted.
CRFTargetList: namespace: "http://nokia.com/yang/isbc-sig" xmlElement: "CRFTargetList" recordElement: "Record"
columnMappings
Maps CIQ column paths to XML tag names. Only needed when the tag name differs from the column name. Sub-table element names are keyed as Record.SubTableName.
columnMappings: "Record.TARGET_LIST_ID": "TARGET_LIST_ID" "Record.CRFTargetListEntry": "CRFTargetListEntry" "Record.CRFTargetListEntry.TG_ID": "TG_ID"
xmlTemplates
Defines exact XML structure for each action using ${placeholder} tokens. Three levels: envelope (wraps all records, has ${records}), record (per CIQ row group, has ${subrecords.Name}), subRecords (per sub-table row). Actions without a template fall back to the programmatic builder.
xmlTemplates: create: envelope: | <config ne="${ne}" ne-version="${ne-version}"> <CRFTargetList xmlns="${namespace}"> ${records} </CRFTargetList> </config> record: | <Record xc:operation="create"> <TARGET_LIST_ID>${Record.TARGET_LIST_ID}</TARGET_LIST_ID> ${subrecords.CRFTargetListEntry} </Record> subRecords: CRFTargetListEntry: | <CRFTargetListEntry> <TARGET_ID>${Record.CRFTargetListEntry.TARGET_ID}</TARGET_ID> </CRFTargetListEntry>
XML TemplatesPlaceholdersOptional — fallback to programmaticSBC

§ 5arollback › precheck
YAML keyrollback.precheck
RunsFirst step of rollback
Node typeSBC
Confirms the records to be deleted still exist on the SBC before issuing DELETE XML. If a record no longer exists, the delete will fail — this step prevents a misleading failure.
show status show alarms active show crf target-list summary show ibcf virtual-network summary

§ 5brollback › configuration  — Auto DELETE XML
YAML keyrollback.configuration
InputCIQ CREATE rows (collected during activity generation)
OutputOne $CREATE_ROLLBACK block per table with CREATE rows
Auto-generates DELETE XML for each table that had CREATE rows. Only primary keys are included — the SBC uses them to identify and remove records. Uses the rollback xmlTemplate if defined, otherwise builds DELETE XML programmatically.
##ACTIVITY_SBC_FL_CRFTargetList_ROLLBACK_CONFIGURATION ## Description: Rollback: delete CRFTargetList records created by this MOP ## TargetNode: OAM_NODE $CREATE_ROLLBACK ACTIVITY_EXECUTION_ACTION_1=CRFTargetList_ROLLBACK_CONFIGURATION ACTIVITY_EXECUTION_METHOD_1=CLI ACTIVITY_EXECUTION_PAYLOAD_1={ cat << 'XMLEOF' > /storage/SBC_FL_CRFTargetList_ROLLBACK.xml <config ne="SBC-1" ...> <CRFTargetList xmlns="..."> <Record xc:operation="delete"> <TARGET_LIST_ID>TL-001</TARGET_LIST_ID> </Record> </CRFTargetList> </config> XMLEOF netconfprov --onerror abort /storage/...xml }
