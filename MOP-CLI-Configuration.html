Part 2 — Section Descriptions
§ 1preNodeHealthCheck
YAML keypreNodeHealthCheck
RunsFirst — before backup or any file change
Node typesMRF, DPA
Confirms the node service is running and files are present before proceeding. Any failure here blocks the entire activity.
date; time service swms status # MRF ls -ltrh /export/.../tools/phoneimport # DPA ps -ef | grep dpa; uptime # DPA
Static CLIRequired
§ 2backup
YAML keybackup
RunsAfter pre-health, before activity
Node typesMRF, DPA
Creates a named backup of the current files. The backup filename (with version/date suffix) is used later during rollback to restore to the pre-activity state.
cp -rp $ANN_DIR ${ANN_DIR}.bkp_$(date) # MRF cp -p phones.dat OldDLUBKP/phones.dat_bkp$VER # DPA
Static CLIRequired
§ 3aactivity › precheck
YAML keyactivity.precheck
RunsBefore execution blocks
Node typesMRF, DPA
Captures a detailed baseline — current directory listing, current version — before making changes. Output is compared with postcheck to confirm the change took effect.
ls -la $ANN_DIR # MRF tail -20 phoneimporter.log # DPA: record current DLU version
Static CLIOptional
§ 3bactivity › execution  — Core Activity (CLI)
YAML keyactivity.execution
RunsBetween precheck and postcheck — this is the actual work
BlocksOne MOP block per list entry — multiple named steps supported
Node typesMRF, DPA (and any future file-based activity)
The core of the CLI-based activity. Each entry becomes a separate named MOP block, allowing logical grouping of steps. Unlike XML mode, commands are written directly in YAML — no CIQ data processing occurs.
MRF — Announcement Loading
name: TRANSFER_ANNOUNCEMENT_FILES → SFTP files to /tmp; ls verify name: LOAD_ANNOUNCEMENT_FILES → cp /tmp/$ANN_FILE $ANN_DIR → chmod 777 $ANN_DIR/$ANN_FILE
DPA — phones.dat Update
name: DEPLOY_PHONES_DAT → cp $NEW_FILE .../phoneimport/phones.dat name: IMPORT_PHONES_DAT → sudo ./importtodpa.sh → tail phoneimporter.log # verify version name: START_PHONES_LOADER → startLoader.sh PHONES
Static CLIRequiredMRFDPA
§ 3cactivity › postcheck
YAML keyactivity.postcheck
RunsAfter all execution blocks
Node typesMRF, DPA
Verifies the file operation completed as expected — correct files present, correct permissions, correct version. Diff against precheck output confirms the change.
ls -la $ANN_DIR # MRF ls -ls phones.dat tail -20 phoneimporter.log # DPA: new DLU version
Static CLIOptional
§ 4postNodeHealthCheck
YAML keypostNodeHealthCheck
RunsAfter all activity blocks
Node typesMRF, DPA
Repeats the pre-health check commands to confirm no degradation. Compares against pre-health baseline. Node service must still be running.
service swms status # MRF df -kh; free -g; ps -ef | grep dpa # DPA
Static CLIRequired
§ 5arollback › precheck
YAML keyrollback.precheck
RunsFirst step of rollback
Node typesMRF, DPA
Confirms the backup created in §2 still exists and is accessible before attempting to restore it. Prevents a failed rollback when the backup was never created or was deleted.
ls -la ${ANN_DIR}.bkp_* # MRF: backup dir exists tail -20 phoneimporter.log # DPA: record current version
Static CLIRequired
§ 5brollback › execution
YAML keyrollback.execution
RunsCore rollback — restores previous state
Node typesMRF, DPA
Restores files from the backup created in §2 and re-runs any import or loader scripts to activate the restored version. If no backup exists, removes the newly added files.
cp -p ${ANN_DIR}.bkp/$FILE $ANN_DIR # MRF cp -p OldDLUBKP/phones.dat_bkp$VER phones.dat sudo ./importtodpa.sh; startLoader.sh PHONES # DPA
Static CLIMRFDPA
§ 5crollback › postcheck
YAML keyrollback.postcheck
RunsFinal step of rollback
Node typesMRF, DPA
Confirms the rollback succeeded. For MRF: announcement directory matches pre-activity state. For DPA: phones.dat version reverted to the backed-up version; new version must differ from current.
ls -la $ANN_DIR # MRF: files restored tail -20 phoneimporter.log # DPA: old DLU version confirmed # DPA guard: if rollback_ver == current_ver → ERROR rollback did not happen
Static CLIRequired
